# 产品说明

> **英文名：Drift**  
> **英文副标题：Your Own Cultural Atlas**  
> **中文名：所见**  
> **中文副标题：你的私人文化地图**


> 版本：v0.4｜平台校准：iPhone-first

**所见（Drift）**是一款以地图为核心界面的私人文化地图产品。

它帮助用户把在阅读、电影、音乐、播客、社交媒体、旅行与日常生活中产生的、与世界各地有关的兴趣、知识与灵感保存下来，并通过空间关系长期积累、整理和重新发现。

产品不是另一个旅游攻略 App，也不是普通地图软件中的地点收藏夹。它更关注人与地方之间较宽泛、私人且文化性的联系，例如：

- 一本与某地强相关的书。
- 一部发生、拍摄或让人联想到某地的电影。
- 一个与某地有关的人物。
- 一段地区历史或社会事件。
- 一个博物馆、墓地、建筑、街区、咖啡馆等具体空间。
- 一种地方文化。
- 一条尚未被整理成完整主题的个人灵感或碎片化想法。

产品希望把“我如何认识世界”的过程空间化。

核心体验可以概括为：

> 看见自己如何认识世界。

## 产品定位

**所见（Drift）**是一个**地图优先、私人使用、允许模糊空间关系的个人文化知识库**。

它不是以导航、POI 信息完整度或旅行攻略为核心，而是通过地图把文化兴趣、知识碎片和个人灵感与国家、城市、地区或具体地点建立关联。

产品遵循以下原则：

- **iPhone-first**：产品最终主要以 iPhone App 形式使用，所有核心交互优先以手机真机体验为准。Web 暂不作为 V1 必需端，未来如出现明确的多端需求再考虑。
- **Map first**：地图不是附属视图，而是最重要的浏览与探索界面。
- **Capture first, organize later**：先记录，再整理，不要求用户在收藏时完成复杂归类。
- **允许模糊空间关系**：内容可以关联国家、城市、地区、精确地点或自定义区域，不要求所有内容都具备准确经纬度。
- **私人优先**：首先服务个人长期积累，不以社区、社交或攻略分享为核心。
- **保持克制**：功能始终围绕“记录—空间关联—重新发现”展开，不发展成臃肿的综合旅行平台。
- **结构由用户逐渐形成**：系统不预先替用户定义世界的分类方式，Tag 与 Topic 随长期使用自然生长。

## 平台策略

- **Primary platform**：iOS / iPhone。
- **主要使用场景**：用户在阅读、观影、听播客、浏览内容或旅行过程中，直接通过手机快速记录和重新发现内容。
- **Web**：V1 暂不承诺。未来如果确有桌面整理、多端访问等需求，可以作为独立客户端补充。
- **数据原则**：即使 V1 只有手机端，也必须保证长期数据可靠保存，并为备份、恢复和未来跨设备同步预留架构空间。
- **账号原则**：账号不是产品核心目标。若未来需要登录，应以数据同步与恢复为主要目的，并保持轻量。
- **系统适配**：界面优先跟随 iOS 的 Light / Dark Mode 与系统语言；首期主要支持中文和 English。

## 核心用户

### 主要用户

- 喜欢阅读、电影、音乐、播客、文化与旅行的人。
- 平时会不断积累与不同国家、城市和地区有关的知识与兴趣。
- 经常在多个平台收藏内容，但缺乏统一、直观的空间化整理方式。
- 希望建立一张“属于自己的世界地图”的用户。
- 重视地图视觉体验，希望地图本身简洁、安静、具有漫游感。

### 用户的典型问题

- **Google Maps / 高德地图**：适合收藏餐厅、酒店、景点等具体 POI，但文化内容容易与普通地点混杂，也不适合表达模糊的文化空间关系。
- **小红书收藏**：收藏来源复杂、内容分散，难以形成稳定结构。
- **备忘录**：缺少空间可视化，信息容易变成扁平文字堆积。
- **普通数据库工具**：可以记录内容，但地图不是核心体验，缺乏空间漫游和兴趣分布的直观感受。

## 主要场景

### 1. 偶然发现与快速记录

这是最高优先级场景。

用户在看书、电影、听播客、听音乐、浏览社交媒体或聊天时，突然遇到一条与某个地方有关的内容，希望快速保存。

例如：

- 《小王子》 → 法国 → 书籍 → 添加备注 → 保存。
- 苏州博物馆 → 苏州 → 地点 / 空间 → `#建筑` → 保存。
- 某部电影 → 巴黎、维也纳 → 电影 → 保存。
- 故宫的空间设计 → 北京 → 保存。

录入时不要求用户先建立 Topic，也不要求精确到具体坐标。

### 2. 地图漫游

用户没有明确旅行任务时，可以打开自己的地图随意浏览：

- 转动、缩放地图。
- 查看哪些国家、城市和地区积累了更多内容。
- 点击一个国家、城市或地区。
- 查看过去在这里保存过的 Entry。
- 重新发现曾经产生过的兴趣。

地图应保持简洁、美观、低信息密度，让用户愿意停留和漫游。

### 3. 旅行前重新发现

当某个国家或城市进入真实旅行计划时，用户可以打开该空间，重新看到过去积累的：

- 书籍
- 电影
- 音乐
- 人物
- 历史 / 事件
- 地点 / 空间
- 文章 / 播客
- Tag
- Topic
- 个人备注

产品不替用户完整生成旅行攻略，而是帮助用户找回：

> 我过去为什么对这里产生兴趣。

### 4. 旅行中的自然使用

V1 不建立复杂“旅行模式”。

但用户到达某个城市后，可以直接查看与当地有关的历史收藏，以及过去想去的具体地点。

### 5. 内容库浏览

除了地图，用户也可以通过统一 Library 查看全部 Entry：

- 搜索内容。
- 按 Type 筛选。
- 按 Tag 筛选。
- 查看或编辑 Entry。
- 后续支持数据导出。

其中：

- **Map = Spatial Browsing**
- **Library = Content Browsing**

## 核心价值

- **把碎片化文化兴趣放回空间中**：用户收藏的不是单纯“地点”，而是与空间发生关联的知识、兴趣和灵感。
- **降低记录门槛**：允许用户先保存碎片，不要求立即完成归纳、分类或 Topic 建设。
- **让长期积累重新产生价值**：今天偶然看到的一本书、一部电影或一段历史，可能在几年后的旅行中重新被激活。
- **形成个人化的世界认知地图**：最终呈现的不只是“去过哪里”或“想去哪里”，而是用户对世界的兴趣分布，以及认识世界的路径。
- **保持地图本身的审美与漫游感**：地图视觉不是装饰，而是产品体验的重要组成部分。

## 初步需求方向

### 1. Entry：核心内容单位

Entry 是产品最基础、最重要的数据对象。

#### Entry Type

V1 暂定：

- 书籍
- 电影
- 音乐
- 人物
- 历史 / 事件
- 地点 / 空间
- 文章 / 播客
- 其他

所有 Entry 都可以独立存在，不要求先归入 Topic。

#### Entry 基础字段

必填：

- `title`
- `type`
- `location`（至少一个空间关联）

核心但可选：

- `note`

其他可选字段：

- `source`
- `creator`
- `year`
- `cover`
- `external_link`
- `tags[]`

自动字段：

- `created_at`

原则：保持字段最小化，不把产品做成完整的书影音资料数据库。

### 2. Tag：用户自定义的轻量分类

Tag 由用户自己创建，不预设固定地点分类体系。

例如：

- `#博物馆`
- `#博物馆`
- `#文学`
- `#想象力`
- `#现代主义`
- `#独立书店`

Tag 可以用于所有 Entry，而不仅限于“地点 / 空间”。

点击某个 Tag 后，可以查看所有相关 Entry，也可以查看这些 Entry 在世界地图上的空间分布。

### 3. Topic：可选的后期归纳层

Topic 不是必填结构。

用户可以先长期积累碎片，等到某个兴趣方向逐渐成形后，再把多个 Entry 归纳成 Topic。

例如：

**Topic：法国文学想象**

可以关联：

- 《小王子》
- 圣埃克苏佩里
- 相关法国电影
- 5·18纪念馆
- 旧全罗南道厅
- 历史笔记

Topic 可以拥有：

- 标题
- 描述
- 笔记
- 多个 Entry
- 多个 Location

产品允许：

> 碎片 → Tag → Topic

但不强制所有内容遵循这一流程。

### 4. Location：空间锚点

Location 是独立于 Entry 的空间对象，用来决定内容“在哪里被重新发现”。

支持：

- `country`：国家
- `city`：城市
- `region`：标准地区 / 行政区域
- `point`：精确地点
- `custom_area`：用户自定义区域

#### 多 Location

一条 Entry 可以关联多个 Location。

例如：

某部电影  
→ 巴黎  
→ 维也纳

不要求 V1 区分主地点和次地点。

#### 空间关系原则

Entry 与 Location 不要求构成严格“属于关系”。

判断标准是：

> 未来当我浏览哪些地方时，希望重新看到这条 Entry？

因此一本书可以只关联法国，也可以同时关联法国与巴黎。

#### 精确地点

当用户确实需要保存具体地点时，可以记录 point 和经纬度。

经纬度只作为底层数据存在，用户无需手动填写。

#### Custom Area / Polygon

允许用户未来手动圈选非标准、模糊或主观定义的空间范围，例如：

- 巴黎左岸
- 某个华北平原相关区域
- 某部电影主要涉及的街区

Custom Area 表达“我的空间理解”，不追求官方行政边界准确性。

Polygon 能力可作为 P1，而非 V1 必须完成。

### 5. 地图浏览与空间面板

默认情况下：

> 点击地图 = 查看，而不是添加。

用户点击国家、城市或地区后：

1. 地图选中该空间。
2. 打开 Spatial Sheet / Panel；在 iPhone 上优先使用 Bottom Sheet。
3. 展示与该空间关联的 Entry。
4. 点击 Entry 后进入 Entry Detail。

地图始终保留在背景中。

### 6. 添加 Entry

全局提供明确的：

`+ 添加`

基础流程：

1. 点击 `+ 添加`
2. 填写标题
3. 选择 Entry Type
4. 添加一个或多个 Location
5. 可选添加 Tag
6. 可选填写 Note
7. 保存

Location 选择方式：

- 搜索
- 在地图上选择

添加模式必须显式进入，避免与正常地图点击冲突。

### 7. 地图展示模式

#### Pure Map

默认地图保持安静，不直接显示大量 Entry marker，只保留国家、主要城市、水域及必要边界。

#### Interest Layer

用户可以开启兴趣分布层。

不同国家、城市或地区根据 Entry 数量呈现轻微 tonal shading，而不是高饱和传统热力图。

用于观察：

> 我的兴趣主要集中在哪里？

#### Tag / Topic 空间分布

当用户选择一个 Tag 或 Topic 时，可以查看它在地图上的空间分布。

原则：

> Entry 更适合阅读，Tag / Topic 更适合观察空间分布。

#### 精确地点 Marker

拥有精确坐标的“地点 / 空间”Entry，只在较高 Zoom Level 下逐渐显示 marker。

低 Zoom Level 不展示大量 marker。

### 8. Library

V1 保留统一内容库。

支持：

- 全部 Entry
- 搜索
- Type 筛选
- Tag 筛选
- Entry Detail
- 后续的数据导出

避免把 Books、Movies、Topics、Tags、Places 等全部拆成一级导航。

### 9. V1 顶层结构

V1 尽量只保留两个一级视图：

#### Map

负责：

- 地图漫游
- 点击国家 / 城市 / 地区
- Spatial Sheet / Panel
- Interest Layer
- Tag / Topic 空间分布
- 从空间进入 Entry

#### Library

负责：

- 全部 Entry
- 搜索
- Type / Tag 筛选
- Entry Detail
- 内容管理

全局提供：

- `+ 添加`
- 搜索

具体位置由 iPhone 交互设计决定，不预先绑定桌面端的顶部栏或侧边栏结构。

### 10. V1 明确不做

暂不加入：

- 社交
- 好友系统
- 内容社区
- 酒店预订
- 机票
- 完整行程规划
- 自动旅游攻略
- 复杂路线导航
- 旅行时间线
- 足迹统计
- 重型旅行日记
- 复杂 POI 数据库
- 官方级地点信息维护
- 过度精细的 Entry 分类体系

## 未来扩展

在核心体验验证之后，可以继续探索：

- 豆瓣书影音导入。
- 与外部书影音数据库联动，补充封面、作者、年份等元数据。
- AI 辅助识别作品与国家 / 城市 / 地区之间的空间关系。
- AI 根据长期积累建议可能形成的 Topic。
- 从多个 Entry 一键创建 Topic。
- 自定义 Polygon / Custom Area 的完整编辑能力。
- “当前位置附近，我过去收藏过什么”的轻量旅行中功能。
- 数据批量导入与导出。
- Topic 专题页。
- 更丰富的 Entry 关系网络。
- 旅行后的照片、笔记或去过状态，但是否纳入核心需根据真实使用反馈决定。

## 当前核心决策

1. 产品不是普通地点收藏地图，而是私人文化地图。
2. Entry 是第一公民。
3. Location 是空间锚点，不要求严格归属。
4. 一个 Entry 可以关联多个 Location。
5. Tag 由用户自由创建，不预设复杂分类体系。
6. Topic 是可选的后期归纳层。
7. 点击地图默认用于查看，添加必须显式进入添加模式。
8. 默认地图不直接展示大量 Entry。
9. 精确地点只在高 Zoom Level 下逐渐出现。
10. Map 与 Library 分别承担空间浏览与内容浏览。
11. 地图美感、留白与可漫游性属于核心产品体验。
12. 产品长期保持克制，不发展成综合旅行平台。
13. iPhone 是主要产品端，Web 暂不进入 V1 核心范围。
14. 长期数据必须支持可靠保存与恢复；登录账号不是目的，必要时仅作为同步与备份手段。
